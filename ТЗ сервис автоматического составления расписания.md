# ТЗ: сервис автоматического составления расписания

Oct 14, 2026 · @kirill

## 1. Общие сведения

Веб-сервис принимает от методиста список дисциплин, групп и преподавателей с их свободным временем и автоматически строит учебное расписание без накладок.

**Цель:** сократить составление расписания на семестр с нескольких дней ручной работы до нескольких минут, исключив конфликты по преподавателям, группам и аудиториям.

**Система делает:**

- принимает дисциплины, количество пар всего и в неделю, группы, преподавателей, аудитории;
- учитывает временные окна преподавателей;
- генерирует расписание на весь учебный период;
- показывает конфликты и даёт править расписание вручную;
- выгружает результат в Excel, PDF и календарь.

**Система не делает (в первой версии):** учёт оплаты и посещаемости, журнал оценок, личный кабинет студента с оценками, интеграцию с внешними учебными системами.

## 2. Пользователи и роли

| Роль | Что делает |
| --- | --- |
| Администратор / методист | Вносит данные, запускает генерацию, правит расписание, публикует и выгружает его |
| Преподаватель | Указывает свои доступные дни и часы, смотрит своё расписание |
| Студент | Смотрит расписание своей группы (только чтение, без входа по ссылке или с входом) |

В MVP достаточно одной роли — методист. Преподаватели и студенты получают только просмотр по ссылке.

## 3. Входные данные

Всё, что система получает перед генерацией. Данные вводятся в интерфейсе или загружаются из Excel/CSV.

| Сущность | Поля |
| --- | --- |
| Учебный период | Дата начала и конца семестра, праздники и нерабочие дни, длительность пары, время начала каждой пары (например, 1-я пара 9:00–10:30) |
| Группа | Название, курс/направление, количество студентов, смена (утро/день/вечер) |
| Дисциплина | Название, тип занятий (лекция/практика/лаба), всего пар за период, пар в неделю, требуемый тип аудитории |
| Учебный план группы | Какие дисциплины изучает группа, у какого преподавателя, сколько пар |
| Преподаватель | ФИО, дисциплины, которые может вести, максимум пар в день и в неделю |
| Доступность преподавателя | Дни недели и интервалы, когда может вести пары; отдельно — запретные окна и разовые отгулы по датам |
| Аудитория | Номер, вместимость, тип (обычная, компьютерный класс, лаборатория), доступность |

**Пример ввода:** дисциплина «Информатика», 36 пар за семестр, 2 пары в неделю, группа ИС-21, преподаватель Иванов, доступен пн/ср/пт с 9:00 до 15:00.

## 4. Правила и ограничения

Жёсткие правила нарушать нельзя: без их выполнения расписание не считается корректным. Мягкие правила система старается выполнить и считает штраф за каждое нарушение.

**Жёсткие ограничения**

1. Преподаватель не ведёт две пары одновременно.
2. У группы не бывает двух пар одновременно.
3. Аудитория занята не более чем одной парой в слот.
4. Пара стоит только в доступное время преподавателя.
5. Вместимость и тип аудитории подходят группе и дисциплине.
6. Количество пар по каждой дисциплине в неделю и за период совпадает с заданным.
7. Занятия не ставятся на праздники и нерабочие дни.

**Мягкие ограничения (с весом)**

| Правило | Вес |
| --- | --- |
| Без «окон» между парами у группы | высокий |
| Не более 4 пар в день у группы | высокий |
| Равномерное распределение пар по дням недели | средний |
| Занятия одной дисциплины не в один и тот же слот каждый день | средний |
| Учёт пожеланий преподавателя (предпочитаемые дни/время) | средний |
| Минимум смен аудитории у группы в течение дня | низкий |
| Лекции в первой половине дня, практики позже | низкий |

Веса настраиваются методистом в интерфейсе.

## 5. Алгоритм генерации

Задача относится к классу NP-трудных задач составления расписаний, поэтому «перебор в лоб» не подходит. Рекомендуемый подход — решатель ограничений **Google OR-Tools CP-SAT** (бесплатный, работает из Python).

**Как это работает**

1. Для каждой пары «занятие × день × номер пары × аудитория» создаётся логическая переменная: занятие стоит в этом слоте или нет.
2. Жёсткие правила из раздела 4 записываются как условия, которые решатель обязан выполнить.
3. Мягкие правила превращаются в штрафы; цель — минимизировать суммарный штраф.
4. Решатель работает ограниченное время (по умолчанию 60 секунд, настраивается) и возвращает лучшее найденное решение.

**Если решения нет.** Система не выдаёт пустой результат, а называет причину: например, «у преподавателя Иванова 12 пар в неделю при доступности 8 слотов» или «не хватает аудиторий типа “компьютерный класс” в среду». Проверка совместимости данных запускается до расчёта.

**Оценка качества.** После генерации показывается итоговый балл: число нарушенных мягких правил с разбивкой по типам.

**Запасной вариант.** Если CP-SAT окажется слишком сложным на старте, для MVP допустим жадный алгоритм с последующей локальной оптимизацией, но при 20–30 группах и более результат будет заметно хуже.

## 6. Функциональные требования

| № | Требование | Приоритет |
| --- | --- | --- |
| 1 | Справочники: добавление, правка, удаление групп, дисциплин, преподавателей, аудиторий | MVP |
| 2 | Учебный план: привязка дисциплин к группам и преподавателям с количеством пар всего и в неделю | MVP |

| 4 | Импорт справочников и учебного плана из Excel/CSV по шаблону, с проверкой ошибок в файле | MVP |
| 5 | Предварительная проверка данных перед расчётом и понятное описание причин, если решения нет | MVP |
| 6 | Запуск генерации с индикатором выполнения и возможностью остановить расчёт | MVP |
| 7 | Просмотр расписания по группе, преподавателю и аудитории в виде недельной сетки | MVP |
| 8 | Ручная правка: перетаскивание пары в другой слот с мгновенной проверкой конфликтов | MVP |
| 9 | Закрепление отдельных пар («зафиксировать»), чтобы повторная генерация их не двигала | версия 2 |

| 12 | Публичная ссылка для студентов и преподавателей | версия 2 |
| 13 | Личные кабинеты преподавателей с самостоятельным вводом доступности | версия 3 |
| 14 | Уведомления об изменениях в расписании (email, Telegram) | версия 3 |

## 7. Интерфейс и экраны

Интерфейс адаптивный: основная работа на компьютере, просмотр готового расписания удобен и на телефоне.

| Экран | Назначение |
| --- | --- |
| Вход | Авторизация методиста по логину и паролю |
| Справочники | Вкладки: группы, дисциплины, преподаватели, аудитории; таблицы с поиском и кнопкой «Импорт из Excel» |
| Учебный план | Таблица «группа — дисциплина — преподаватель — пар всего — пар в неделю» |
| Доступность преподавателя | Сетка «день × пара» с тремя состояниями ячейки |
| Параметры расчёта | Период, длительность пары, веса мягких правил, лимит времени расчёта |
| Генерация | Кнопка «Составить расписание», прогресс, отчёт о проблемах данных |
| Расписание | Недельная сетка с переключателем «по группе / по преподавателю / по аудитории», перетаскивание пар, подсветка конфликтов красным |
| Отчёт о качестве | Итоговый балл, список нарушенных мягких правил, загрузка преподавателей и аудиторий |
| Экспорт | Выбор формата и фильтра (вся организация, одна группа, один преподаватель) |

**Основной сценарий:** загрузить справочники → заполнить учебный план → отметить доступность преподавателей → нажать «Составить» → проверить отчёт → поправить вручную → выгрузить.

## 10. Нефункциональные требования и стек

**Требования**

- Масштаб MVP: до 50 групп, 100 преподавателей, 60 аудиторий, один семестр.
- Время генерации: до 2 минут для типового набора данных, при превышении возвращается лучшее найденное решение.
- Время отклика интерфейса: до 1 секунды на обычные действия.
- Доступ только по логину и паролю, пароли хранятся в виде хэша, соединение по HTTPS.
- Ежедневная резервная копия базы данных.
- Работа в современных браузерах (Chrome, Edge, Firefox, Safari) и на мобильных устройствах для просмотра.
- Интерфейс на русском языке.

**Рекомендуемый стек**

| Слой | Технология | Почему |
| --- | --- | --- |
| Интерфейс | React или Vue, библиотека для drag-and-drop и календарной сетки | Удобная недельная сетка с перетаскиванием |
| Сервер | Python + FastAPI | Тот же язык, что и у решателя |
| Решатель | Google OR-Tools (CP-SAT) | Бесплатный, подходит для расписаний |
| База данных | PostgreSQL | Надёжно, много связей между таблицами |
| Фоновые задачи | Celery или встроенная очередь | Генерация идёт в фоне, интерфейс не блокируется |
| Экспорт | openpyxl (Excel), WeasyPrint (PDF), icalendar | Готовые библиотеки |
| Хостинг | VPS с Docker | Просто развернуть и перенести |

## 11. Этапы разработки

Сроки ориентировочные, для одного разработчика, работающего с ИИ-помощником.

| Этап | Что входит | Срок |
| --- | --- | --- |
| 0. Подготовка | Уточнение правил у заказчика, сбор реальных данных для теста, макеты экранов | 1 неделя |
| 1. MVP | Справочники, учебный план, доступность, импорт Excel, генерация на CP-SAT, просмотр и ручная правка, экспорт в Excel и PDF | 4–6 недель |
| 2. Версия 2 | Закрепление пар, версии расписания, замены, iCal, публичная ссылка | 3–4 недели |
| 3. Версия 3 | Кабинеты преподавателей, уведомления, несколько филиалов или корпусов | 4–6 недель |

К MVP можно переходить к пробному использованию на одном потоке групп, а остальное добавлять по обратной связи.

## 12. Приёмка, риски и открытые вопросы

**Критерии приёмки MVP**

- [ ] На реальных данных (не менее 10 групп и 20 преподавателей) расписание строится за время не более 2 минут.
- [ ] В готовом расписании нет ни одного нарушения жёстких правил (проверка автоматическим тестом).
- [ ] Ручное перетаскивание пары в занятый слот блокируется или подсвечивается с указанием причины.
- [ ] Если данные противоречивы, система называет конкретную причину, а не просто сообщает об ошибке.
- [ ] Выгрузка в Excel и PDF открывается без правок и содержит все пары группы или преподавателя.
- [ ] Импорт из Excel сообщает номер строки и причину для каждой ошибки.

**Риски**

| Риск | Что делать |
| --- | --- |
| Правила колледжа сложнее, чем описано (например, потоки лекций на несколько групп, подгруппы) | Собрать все реальные правила на этапе 0, заложить поддержку потоков и подгрупп в модель данных заранее |
| Слишком много ограничений, и решения нет | Предварительная проверка данных и отчёт о причинах, возможность ослабить правило |
| Расчёт слишком долгий | Лимит времени, возврат лучшего найденного решения, поэтапная генерация по потокам |
| Преподаватели не заполняют доступность | В MVP доступность вводит методист, кабинеты преподавателей только в версии 3 |

**Вопросы к заказчику**

- Нужны ли подгруппы (деление группы на две для практик) и общие лекции для нескольких групп?
- Одна смена или несколько, есть ли занятия по субботам?
- Сколько корпусов, и нужно ли учитывать время перехода между ними?
- Нужно ли расписание на весь семестр по датам или достаточно типовой недели с чётной/нечётной сменой?
- Сколько человек будет пользоваться системой и нужны ли разные права доступа?
