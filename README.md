# Сервис автоматического составления расписания

MVP по документу «ТЗ сервис автоматического составления расписания.md»: методист заполняет справочники, учебный план и доступность преподавателей, а система строит расписание на весь семестр без накладок и выгружает его в Excel, PDF и календарь.

## Быстрый старт (Windows, локально)

**[Скачать установщик для Windows — Schedule-Setup-1.0.0.exe (57 МБ)](https://github.com/balagarsage3-web/schedule-desktop/releases/download/v1.0.0/Schedule-Setup-1.0.0.exe)**

Все выпуски доступны в [GitHub Releases](https://github.com/balagarsage3-web/schedule-desktop/releases).
Скачайте exe по ссылке выше и запустите его. Мастер на русском языке установит приложение
и создаст ярлык. Python и Node.js устанавливать отдельно не нужно.
Если нет Microsoft WebView2, мастер установит его через интернет.
Приложение работает в отдельном окне; подробности сборки и хранения данных —
в `desktop/README.md`.

**Запуск из исходников:** выполните `run.ps1` по инструкции ниже.
При необходимости сначала соберите дополнительный запускатель командой
`powershell -ExecutionPolicy Bypass -File launcher/build.ps1`, затем нажмите
**`Расписание.exe`** в корне проекта. Запускатель поднимает сервер
и открывает приложение в браузере. Окно сервера оставьте открытым; для остановки
нажмите Ctrl+C или закройте окно. Повторный запуск открывает уже работающий сервер.

Exe использует папки `backend` и `frontend` рядом с собой, включая установленное
окружение `backend/.venv` и собранный интерфейс `frontend/dist`. Это запускатель
проекта, а не автономный установщик: при переносе на другой компьютер сначала
установите Python и Node.js и выполните `run.ps1`. Исходник запускателя находится
в `launcher/Launcher.cs`, пересборка: `powershell -ExecutionPolicy Bypass -File launcher/build.ps1`.

Альтернативный запуск и первоначальная установка зависимостей:

```powershell
.\run.ps1
```

Откройте http://127.0.0.1:8000. Логин `admin`, пароль `admin` (смените в «Параметрах расчёта» → «Служебное»).
Чтобы сразу посмотреть систему в работе, нажмите **«Загрузить демо-данные»** на экране «Параметры расчёта» (колледж из 12 групп), затем **Генерация → Составить расписание**.

Режим разработки интерфейса: `cd frontend; npm run dev` (http://localhost:5173, запросы к API проксируются на :8000).

## Развёртывание на VPS (Docker)

```bash
cp .env.example .env    # заполните DOMAIN, пароли и SECRET_KEY
docker compose up -d --build
```

Поднимаются PostgreSQL, приложение, Caddy (HTTPS с сертификатом Let's Encrypt для `DOMAIN`) и контейнер ежедневного резервного копирования (`./backups`, хранятся последние 14 копий).

## Как устроено

| Слой | Технология |
| --- | --- |
| Интерфейс | Vue 3 + Vite, перетаскивание на нативном HTML5 drag-and-drop |
| Сервер | Python, FastAPI |
| Решатель | Google OR-Tools CP-SAT |
| База данных | SQLite локально, PostgreSQL в Docker (`DATABASE_URL`) |
| Фоновые задачи | встроенная очередь на потоках: генерация не блокирует интерфейс, её можно остановить |
| Экспорт | openpyxl (Excel), ReportLab (PDF), iCal формируется вручную по RFC 5545 |

**Алгоритм** (`backend/app/solver/`):

1. `problem.py` — **нагрузка по неделям**. Строки из КУГ берут часы недели прямо из графика (2 часа = 1 пара, нечётные часы накапливаются). Строки без КУГ раскладывают «пар всего» по «пар в неделю» в своих сроках (начало/окончание) с учётом ёмкости недели: неполные недели, праздники, отгулы, доступность и лимиты преподавателя, слоты группы. Если в какой-то неделе пары не помещаются, они догоняются позже.
2. `precheck.py` — проверка данных до расчёта. Причины называются конкретно: «У преподавателя Иванов А.А. 12 пар в неделю при доступности 8 слотов», «не назначен преподаватель — …», «неделя 06.10–12.10: у группы 20 пар при 18 слотах». Перегрузка отдельной недели — предупреждение (лишние пары перейдут дальше), нехватка мест за весь период — ошибка.
3. `cpsat.py` — CP-SAT расставляет **каждую неделю** по её собственной нагрузке: булева переменная на каждое «занятие × день × пара». Решение прошлой недели служит подсказкой, а правило «стабильность» штрафует переезды, поэтому расписание от недели к неделе меняется только там, где меняется КУГ. Недели с одинаковой нагрузкой решаются один раз. Сначала пробуется строгая постановка (все пары обязательны). Если неделю так не уложить, недобор допускается и переносится на следующую неделю. Аудитории учитываются через условие Холла по типу и порогам вместимости.
4. `expand.py` — проходит недели по порядку, делит лимит времени между разными неделями и назначает аудитории. Предпочтения: та же аудитория, что неделю назад, затем аудитория предыдущей пары, затем «своя» аудитория группы.
5. `validate.py` — независимая проверка всех жёстких правил и подсчёт мягких. Она же подсвечивает конфликты в сетке и формирует отчёт о качестве.

Производительность на демо-данных (лимит = общее время на период): 18 групп — около 50 с, 40 групп / 49 преподавателей — около 95 с. Две группы по реальному КУГ (полугодие) — несколько секунд.

## КУГ (календарный учебный график)

Экран **«КУГ»** → «Импорт КУГ из Excel»:

1. Загрузите файл графика: лист на курс, часы по неделям, «К» — каникулы.
2. Выберите курс (лист) и группы.
3. Укажите, ставить ли в расписание самостоятельную работу и учебную практику. Производственная практика, экзамены и ГИА в сетку пар не попадают.
4. Можно сразу создать учебные периоды (полугодия) по датам графика.

Даты недель берутся из чисел месяца в шапке, а не из «номеров календарных недель». В присланных шаблонах они местами скопированы со сдвигом, например в IV курсе 2027–2028.

После импорта на экране «Учебный план» отметьте строки «без преподавателя» и назначьте преподавателя сразу всем выбранным. На вкладке «Нагрузка по неделям» видна сетка «дисциплина × неделя». Часы КУГ правятся щелчком по ячейке, а итог недели сравнивается с числом слотов смены группы.

## Тесты

```powershell
cd backend; .venv\Scripts\python -m pytest -q
```

Тесты повторяют критерии приёмки MVP: 18 групп / 21 преподаватель — расписание за < 2 минут и без нарушений жёстких правил; противоречивые данные — конкретная причина; перенос в занятый слот — блокировка с объяснением; выгрузки содержат все пары группы; импорт сообщает строку и причину каждой ошибки.

## Допущения (вопросы из раздела 12 ТЗ, требующие ответа заказчика)

- Общие пары для нескольких групп поддерживаются через поле «Поток». Подгрупп (деления одной группы на две) пока нет.
- Каждая неделя строится по своей нагрузке (из КУГ или «пар в неделю»), неизменные пары стараются остаться на прежних местах. Отдельного режима «чётная/нечётная неделя» нет, но по КУГ он получается сам, если нагрузка чередуется.
- Пара = 2 академических часа (`HOURS_PER_PAIR` в `models.py`).
- Время перехода между корпусами не учитывается.
- Используется одна роль — методист.
- Для PDF вместо WeasyPrint взят ReportLab: WeasyPrint требует системных библиотек GTK, которые на Windows ставятся с трудом.
